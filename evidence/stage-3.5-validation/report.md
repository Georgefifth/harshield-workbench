## 1. Validation Objectives & Capability Scope

The objective of Stage 3.5 is to evaluate **HARshield Workbench** on external, real-world `.har` captures from open-source repositories (`mitmproxy`, `Netflix/pollyjs`, `cloudflare/har-sanitizer`, `sitespeedio/coach-core`) as well as adversarial encoding edge cases, measuring:
1. **Dialect & Schema Resilience**: Handling real-world HAR variations generated by mitmproxy, Chrome, Firefox, Puppeteer, and Polly.JS.
2. **Secret Recall & Zero-Leak Accuracy**: Percentage of ground-truth credentials/PII removed across headers, cookies, query strings, JSON request/response bodies, form payloads, Base64-encoded JSON bodies, and double-encoded JSON-in-JSON strings.
3. **False-Positive Resistance (Negative Cases)**: Ensuring clean public HTTP captures (`example.com`, `httpbin.org`) produce `0` bogus redactions.
4. **Output Structural Validity**: Guaranteeing 100% `JSON.parse()` validity after sanitization (unlike regex scrubbers).
5. **Direct Competitor Benchmark**: Running the exact `sanitize()` regex implementation from `cloudflare/har-sanitizer` (`src/lib/har_sanitize.tsx`) and Chrome 130+'s header-only scrubber on the identical 12-file corpus.

## 3. Initial Validation Run & Failure Root-Cause Analysis (`initial-results.json`)

Before modifying any engine code in Stage 3.5, we executed `npx vite-node scripts/run-stage3.5-validation.ts --phase=initial` and saved the raw results to `evidence/stage-3.5-validation/initial-results.json`.

- **Initial Pass Rate**: **8 / 12 cases (66.7%)**
- **Initial Secret Recall**: **20 / 27 (74.1%)**

### Root-Cause Analysis of Initial Failures

1. **`RW-06-pollyjs-users-array-headers.har` (Input Dialect Exception)**:
   - **Failure**: `Runtime exception during sanitization: cookieHeaderVal.split is not a function`.
   - **Root Cause**: `Netflix/pollyjs` v1.4.1 serializes multi-value HTTP headers as a JSON Array `value: ["__cfduid=d9290fa7..."]` rather than a string. `sanitizeCookieHeaderString` assumed `h.value` was always a `string`.
   - **Fix**: Normalized `Array.isArray(h.value)` to `h.value.join('; ')` in `processHeaders()` and `runCompetitorAudit()`.
2. **`RW-01-mitmproxy-diff-data.har` (Missing Header/Query Keys & Unstructured Protobuf Echo)**:
   - **Failure**: Missed `x-client-data`, Slack `session_id`, and `client_id=PyIKPe4Z1cTqdvB7d+FPCQ==` (which was redacted in `queryString` but echoed raw inside an `application/vnd.google.octet-stream-compressible` binary-text protobuf body).
   - **Fix**: Added `x-client-data`, `session_id`, and `client_id` to the detector lists, added Google (`ya29.`, `AIza...`) and Slack (`xoxd-...`) token patterns, and implemented `pseudonymizer.scrubKnownSecretsInUnstructuredText()` so any secret (`>= 8` chars) discovered in structured headers/query/JSON is also scrubbed if echoed inside unstructured bodies.
3. **`RW-07-cloudflare-unit-fixture.har` (Unquoted Inline `key=value` inside Custom Headers)**:
   - **Failure**: Missed `mysupersecret` and `app123` inside `X-Custom-Auth: client_secret=mysupersecret&client_id=app123`.
   - **Root Cause**: `sanitizeInlineQuotedHeader` only matched quoted `key="value"`, not unquoted `key=value&key2=value2`.
   - **Fix**: Expanded `sanitizeInlineHeaderKeyValues()` to parse both quoted `k="v"` and unquoted `k=v` pairs delimited by `&`, `;`, or `,`.
4. **`RW-10-base64-encoded-response-json.har` & `RW-11-double-encoded-json-in-json.har` (Nested Encoding Layers)**:
   - **Failure**: `RW-10` did not decode `encoding: "base64"` JSON response bodies before AST traversal; `RW-11` did not recursively parse stringified JSON objects (`"{\"password\":\"...\"}"`) inside outer JSON properties.
   - **Fix**: Added Base64 JSON decode → `walkJsonAst` → Base64 re-encode in Section 5 of `recursiveSanitizer.ts`, and added recursive inner-JSON parsing in `walkJsonAst()` when a string value is a valid JSON object/array literal.
5. **UI Presentation Polish Discovered via Browser Upload (`01-rw01-mitmproxy-uploaded.png`)**:
   - Uploading `RW-01-mitmproxy-diff-data.har` in Chromium showed 14-digit Python float timings (`85.77585220336914ms`) in the waterfall. Fixed via `Math.round(entry.time || 0)` in `src/App.tsx` and `src/engine/reproExporter.ts`.

## 5. Honest Assessment of Remaining Capabilities Not Supported

Per `prompts/03.5-validation.md` Section 7.10, we explicitly document the boundaries of what HARshield Workbench does **not** currently process:
1. **Hex-Chunked Gzip Binary Arrays (`Polly.JS` `_isBinary: true` Node-Fetch Format)**: During our inspection of `Netflix/pollyjs`'s `node-fetch` adapter (`RW-06`), we observed that when `content-encoding: gzip` is recorded by `Polly.JS` in Node.js without decompression, `response.content.text` is stored as a JSON array of raw hex-encoded gzip chunks (`["1f8b0800..."]`). While HARshield sanitizes `RW-06`'s array-typed headers (`set-cookie`), it does not run gunzip decompression on hex-chunked `_isBinary: true` arrays in the browser. (Standard browser DevTools HAR exports from Chrome, Firefox, Edge, and Safari always export decompressed UTF-8 or `encoding: "base64"` text, which HARshield supports 100%).
2. **Custom Binary Protobuf Schema Decoding**: For `application/vnd.google.octet-stream-compressible` (`RW-01`), HARshield scrubs emails, known token prefixes (`ya29.`, `AIza...`), and any secret value correlated with structured headers/query params, but does not parse arbitrary `.proto` wire tags without a schema.
